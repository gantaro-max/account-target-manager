# 実装パターン早見表

Agent-C・Agent-D・実装AI が「実装パターンの一貫性」を判断する際の共通リファレンス。

## このドキュメントの目的

「既存コードと同じ書き方にする」は人間には伝わりますが、AIエージェントには伝わりません。
毎回コードベース全体を読ませるのは非効率で、しかも読む範囲によって結論がブレます。

そこで **「同じことをする方法は1つに固定し、表として明示する」** という方針を取ります。
これにより「一貫性」という主観的な観点が、チェックリストで機械的に検証できる客観的な観点に変わります。

## 運用ルール

- 新しいパターンが確立されたタイミングで**随時追記**する（最初から網羅しようとしない）
- 同じ用途に2つ目の書き方が現れたら、**どちらかを正解に決めて**表を更新し、もう一方は既存コードごと寄せる
- 表にないパターンを実装AIが新規に採用した場合、Agent-C はそれを**指摘対象**とする
  （悪い実装だからではなく、「表に載せる価値があるか Claude が判断していない」ため）

## ローディング表示

| 用途 | 正解パターン |
|---|---|
| 通常のバックエンド呼び出し（保存・削除・同期等） | `<関数呼び出し>` → 完了後 `<解除の呼び出し>` |
| ファイルダウンロード系の呼び出し | `<別パターン>` |

## エラーハンドリング

| 用途 | 正解パターン |
|---|---|
| 通信失敗ハンドラ | `<パターン>` |
| フォームバリデーション失敗 | `<パターン>` |

## ダイアログ

| 用途 | 正解パターン |
|---|---|
| 削除確認 | `<ボタン文言・アイコン種別まで固定する>` |
| 保存成功トースト | `<パターン>` |
| 該当なし通知 | `<パターン>` |

## ファイル出力

| 項目 | 正解パターン |
|---|---|
| 文字コード | `<BOM の有無まで明記する>` |
| ファイル名形式 | `<"機能名_条件_YYYY-MM-DD.拡張子" のような規則>` |
| 出力後のリソース解放 | `<パターン>` |

## DOM操作・セキュリティ

| 用途 | 正解パターン |
|---|---|
| 動的テキスト挿入 | `element.textContent = value`（`innerHTML` への直接代入禁止） |
| HTMLテンプレートへのデータ埋め込み | `<エスケープ関数>` を経由する |

## スタイル・クラス名

| 用途 | 正解パターン |
|---|---|
| ツールバーボタン | `class="<クラス名>"` |
| <用途> | `<パターン>` |
