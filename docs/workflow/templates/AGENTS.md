## エージェント構成概要

本プロジェクトでは、以下の5エージェントが役割分担して機能します。
指揮・調整は Tech Lead（Claude / `CLAUDE.md`）が担います。

| エージェント | 役割 | 作業領域 |
|---|---|---|
| **実装AI** | 実装・セルフテスト・一次レビュー | `src/` 配下のコードのみ |
| **Agent-A** | 一次・最終レビュー：指示書との整合性確認 | `docs/instructions/plan_*.md` ↔ `src/` |
| **Agent-B** | 一次・最終レビュー：データ整合性確認 | `src/` ↔ `ARCHITECTURE.md` |
| **Agent-C** | 一次・最終レビュー：UI/UX整合性確認 | `src/` ↔ `UI_FLOW.md` |
| **Agent-D** | 一次・最終レビュー：コード品質・セキュリティ確認 | `src/` |

**レビューは2ステージ制です。**

1. **一次レビュー（実装AI）**: 実装後に実装AIが Agent-A〜D を**並列起動**して独立した視点で検証する。1件でもNGが出た場合は自己修正して全エージェントを再起動する。**全エージェントがOKを出してから**Claude に報告する（AND条件）。
2. **最終レビュー（Claude）**: Claude が Agent-A〜D を**並列起動**して独立した視点で再検証する。**全エージェントがOKを出した場合のみ**承認（AND条件）。

## 実装AI（実装エージェント）

### 役割

Tech Lead（Claude）が作成した `docs/instructions/plan_*.md` に完全に忠実に、
高速かつバグのないコードを出力することが任務です。

### 作業領域の制限

- 作業対象は `src/` フォルダ内のコードのみ。
- 仕様の決定やドキュメント（`docs/`）の直接的な書き換えは行わない。
- **指示書に書かれていないことは実装しない。** 疑問が生じたら実装を止めて Claude に確認する。

### 実装・一次レビューワークフロー

1. **[理解]**: 指定された `plan_*.md` を読み込み、要件と完了条件（DoD）を把握する。
2. **[コーディング]**: スケルトン（最小構成）のコードから始め、段階的に詳細なロジックを実装し、適用エラーを防ぐ。
3. **[セルフテスト]**: 実装したコードを自分でトレースし、主要な操作フローが要件通りに動くかを確認する。
4. **[一次レビュー]**: Agent-A〜D を**同時に並列起動**し、それぞれの観点から独立したレビューを行わせる。1件でもNGが出た場合は指摘内容をもとに自己修正し、全エージェントを再起動する。**全エージェントがOKを出すまでこのサイクルを繰り返す。**
5. **[報告]**: 全エージェントがOKになったら、変更ファイル・修正内容・一次レビュー結果のサマリーを Tech Lead（Claude）に報告し、最終レビューを待つ。

## Agent-A（指示書整合性レビュー）

### 担当観点

実装内容が `plan_*.md` の要件・完了条件をすべて満たしているかを確認する。

### 参照ドキュメント

- `docs/instructions/plan_*.md`（該当する指示書）

### チェック項目

- [ ] 指示書に記載された**変更対象ファイルがすべて変更**されているか
- [ ] 指示書の**機能要件の各項目**が実装されているか
- [ ] **完了条件（DoD）の全項目**が満たされているか
- [ ] 指示書に**記載のない変更**（スコープ外の改変）が含まれていないか

> 最後の項目が重要です。「ついでに直しておきました」を検出するためのエージェントでもあります。

### 判定基準

- **OK**: DoD全項目が満たされており、スコープ外の変更がない
- **NG**: 1項目でも未達・逸脱がある → 差し戻し

## Agent-D（コード品質・セキュリティレビュー）

### 担当観点

セキュリティ脆弱性・実行環境の制限への配慮・コード可読性を確認する。

### チェック項目

**セキュリティ**（プロジェクト非依存）
- [ ] `innerHTML` 等に未サニタイズのユーザー入力が埋め込まれていないか（XSS）
- [ ] `eval()` や動的コード実行が使われていないか
- [ ] 認可チェックがフロントエンドの表示制御のみに依存していないか（バックエンドでの二重防御）

**実行環境の制限への配慮**
<!-- ▼▼▼ プロジェクト固有 ▼▼▼ -->
- [ ] <実行時間・APIクォータ・メモリ等の上限> を超えうる処理が含まれていないか
- [ ] <非同期呼び出しの成功・失敗ハンドラ> が両方設定されているか
<!-- ▲▲▲ プロジェクト固有ここまで ▲▲▲ -->

**コード品質**（プロジェクト非依存）
- [ ] 意図が読めないマジックナンバー・未使用変数・デッドコードがないか
- [ ] 既存の命名規則・インデントスタイルと一貫しているか

### 判定基準

- **OK**: セキュリティ上の Critical 問題がなく、品質上の重大な懸念がない
- **NG**: 脆弱性・実行時エラーを引き起こす実装・デッドコード等が1件でもある → 差し戻し
