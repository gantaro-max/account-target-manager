- [ ] **ユーザーマスター拡張（論理削除フラグ・ソート順カラム）**
  - `users` シートに以下の2カラムを追加し、担当者の退職・異動対応と表示順の統一を実現する。
  - **`is_active` カラム（論理削除フラグ）**
    - 値: `TRUE`（有効）/ `FALSE`（無効＝退職・異動済み）。デフォルト `TRUE`。管理者がスプレッドシートを直接編集。
    - `FALSE` のユーザーを**非表示にする場所**: 担当者セレクター全般（統計タブ・サマリータブ・他担当者閲覧セレクター）、統計タブの担当者別グラフ。

    - 過去の活動ログ・ステージ変更履歴の `changed_by` 等に残る記録はそのまま保持（データは削除しない）。
  - **`sort_order` カラム（表示順）**
    - 値: 整数（例: 1, 2, 3...）。管理者がスプレッドシートを直接編集。`NULL` のユーザーは末尾に表示。
    - 統一する場所: 担当者セレクター全般・担当者別グラフの棒の並び。

  - **フロントエンド**: `db.users` 取得後、セレクター構築時に `is_active` でフィルタ・`sort_order` で並び替え。引継ぎ機能の離任者セレクターのみ `is_active=FALSE` を含む全員を対象にする。

## 4. 🛠 既知の制限事項

- **同時編集の競合**: 複数人が同じ取引先データを同時に編集した場合、後の保存が優先される（Last-Write-Wins）。
- **GASのクォータ**: ファイル転送量や実行時間はGoogle Apps Scriptの制限に依存する。
