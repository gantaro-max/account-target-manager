# 実装指示書：他担当者取引先参照機能

**作成日**: 2026-05-20  
**対象ロール**: `member` / `leader`  
**想定取引先総数**: 全担当者合計で最大120件程度  
**データ取得方式**: 方式C（ハイブリッド取得）

---

## 1. 背景・目的

現状、`member`/`leader` ロールは自身が登録した取引先しか参照できない。他担当者の取引先も閲覧できるようにすることで、チーム内の情報共有・引き継ぎ・相互サポートを可能にする。他担当者の取引先は**閲覧のみ**とし、データ改ざんを防ぐ。

取引先数は最大120件だが、活動ログは月次で積み上がるため全件一括取得は避ける。初回ロードでは他担当者の**取引先名リストのみ**を取得し、取引先を選択したタイミングで詳細データを追加取得するハイブリッド方式を採用する。

## 3. データ取得設計（方式C ハイブリッド）

### 3.1 初回ロード（`getData()` の変更）

| データ | 自分の取引先 | 他担当者の取引先 |
|---|---|---|
| 取引先基本情報 | 全件取得（現状どおり） | **取引先名・ID・担当者情報のみ**取得（軽量） |
| 部署 | 全件取得（現状どおり） | **取得しない** |
| 案件 | 全件取得（現状どおり） | **取得しない** |
| 活動ログ | 全件取得（現状どおり） | **取得しない** |

**サーバー側実装イメージ**（`getData()` に追記）:

```javascript
// leader/member ロールのユーザーが登録した取引先の軽量リストを返す
const leaderMemberEmails = new Set(
  _getRows(SHEET.USERS)
    .filter(r => r.role === "leader" || r.role === "member")
    .map(r => r.email)
);
const otherAccounts = _getRows(SHEET.ACCOUNTS)
  .filter(h =>
    leaderMemberEmails.has(h.assigned_user_id) &&
    h.assigned_user_id !== email  // 自分の取引先は除く
  )
  .map(h => ({
    id: h.id,
    name: h.name,
    assignedUserId: h.assigned_user_id,
    assignedUserName: allUsers.find(u => u.email === h.assigned_user_id)?.name || ""
  }));

// 戻り値に追加
return {
  // ... 既存のフィールド ...
  otherAccounts,  // 追加
};
```

> `admin`/`manager` ロールの場合は `otherAccounts` を空配列で返す（担当者セレクター自体を非表示にするため不要）。

### 3.2 取引先詳細の動的取得（新関数 `getAccountDetail(accountId)`）

他担当者の取引先が初めて選択されたタイミングで呼び出す。

```javascript
function getAccountDetail(accountId) {
  // 指定した accountId に紐づく部署・案件・ログを返す
  // 権限チェック: 呼び出し元が leader/member であること、
  //              かつ対象取引先の assigned_user_id が leader/member であることを確認
  return {
    departments: [...],  // 対象取引先の部署
    projects:    [...],  // 対象取引先の案件
    logs:        [...],  // 対象取引先の活動ログ
  };
}
```

### 3.3 クライアント側キャッシュ

一度取得した取引先の詳細はメモリにキャッシュし、再選択時は再取得しない。

```javascript
const otherAccountCache = {};  // { [accountId]: { departments, projects, logs } }

async function ensureAccountDetail(accountId) {
  if (otherAccountCache[accountId]) return;  // キャッシュ済みならスキップ
  // ローディング表示
  showOverlay("データを読み込んでいます...");
  const detail = await callGAS("getAccountDetail", accountId);
  otherAccountCache[accountId] = detail;
  hideOverlay();
}
```

> キャッシュはページリロードまで保持。ブラウザをリロードすれば最新データを再取得する。

## 5. 担当者セレクター UI

### 5.1 配置場所

- 📝 **活動&アクション** タブ：取引先選択プルダウンの**左横**
- 🔭 **取引先ダッシュボード** タブ：取引先選択プルダウンの**左横**（独立配置・各タブで状態を保持）

### 5.2 表示条件

- `member` / `leader` ロール：担当者セレクターを表示
- `admin` / `manager` ロール：担当者セレクターを表示しない（全件参照のため不要）

### 5.3 選択肢（`member` / `leader` 共通）

```
自分（デフォルト）
他担当者
──────────────
担当者A の名前
担当者B の名前
…
```

- ユーザーリストは `allUsers` から `role === "leader" || role === "member"` かつ `email !== currentUserEmail` で抽出
- `manager` / `admin` はリストに含めない

### 5.4 取引先プルダウンのグループ表示

「他担当者」または個別担当者を選択した場合、取引先プルダウンを `<optgroup>` で担当者名ごとにグループ分けする。Tom Select は `<optgroup>` を自動でグループ見出し付きに描画する。

```html
<optgroup label="田中 太郎">
  <option value="h001">〇〇取引先</option>
  <option value="h002">△△取引先</option>
</optgroup>
<optgroup label="山田 花子">
  <option value="h003">□□取引先</option>
</optgroup>
```

> 視覚的に問題がある場合は、取引先名の後ろに担当者名を添えるフラット表示（例：`〇〇取引先（田中）`）に変更する。

## 6. 取引先選択時の動作フロー

```
担当者セレクター変更
  │
  ├─ 「自分」選択
  │    └─ 取引先プルダウンを自分の db.accounts で再構築
  │         取引先選択 → 通常どおり（フォーム表示・編集可）
  │
  └─ 「他担当者」または個別担当者選択
       └─ 取引先プルダウンを db.otherAccounts（軽量リスト）で再構築（グループ表示）
            取引先選択
              │
              └─ ensureAccountDetail(accountId) を呼び出し
                   │
                   ├─ キャッシュあり → そのまま描画
                   └─ キャッシュなし → GAS呼び出し → キャッシュ保存 → 描画
                        （ローディングオーバーレイを表示）

            描画内容（閲覧のみ）
              ├─ 案件カード一覧（読み取り専用表示）
              ├─ 活動ログ履歴（読み取り専用表示）
              └─ ログ入力フォームは非表示
```

---

## 7. アクセス制御（活動&アクション タブ）

| 状態 | ログ入力フォーム | 案件カード | 活動ログ履歴 |
|---|---|---|---|
| 自分の取引先を選択 | 表示・編集可 | 表示・編集可 | 表示・編集可 |
| 他担当者の取引先を選択 | **非表示** | 表示のみ | 表示のみ |

フォーム非表示の実装は既存の `manager-hidden` クラスを流用するか、新たに `other-user-mode` クラスを設けて切り替える。

---

## 8. クラウド同期（Upsert）の扱い

**変更なし**。同期対象は引き続き `assigned_user_id === 自分のemail` の取引先のみ。`otherAccountCache` のデータは同期に含めない。`syncAll()` 内の取引先スコープ確定ロジックは現状を維持する。
