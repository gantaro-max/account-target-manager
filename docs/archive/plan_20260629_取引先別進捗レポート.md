# 取引先別進捗レポート出力機能の追加

## 1. 背景・目的

活動＆アクションタブに「取引先別進捗レポート」出力ボタンを追加する。
担当MS等の取引先担当者と進捗を共有するため、自担当の全取引先・全案件（受注失注含む）を
1行＝1案件＋直近ログ形式でCSV出力する。
対象取引先はダイアログの選択式とし、「全取引先」または特定の1取引先を選んで出力できる。

### src/コード.js — `getAccountReport(accountId)` 関数

`getProjectReport` 関数の直後（`getStatistics` 関数の前）に以下の仕様で追加する。

- 関数冒頭で `_requireRegisteredUser()` を呼ぶ。
- アクセス制御: `getCsvData` と同じスコープ。`admin`/`manager` は全取引先、それ以外は `assigned_user_id === email` の取引先のみ対象。
- `accountId` が `"all"` 以外の場合、スコープ内の取引先をさらにその1件に絞り込む。
- 対象取引先が0件なら `null` を返す。
- **直近ログ取得**: `_getRows(SHEET.LOGS)` の中から、各プロジェクトIDごとに `visit_date` 文字列が最大のログ1件を選択する。ログなしの案件は直近ログ列を空欄で出力（案件行は省略しない）。
- **出力列（この順番で）**:
  1. 担当者名（`users.name`、なければ `assigned_user_id`）
  2. 取引先名（`accounts.name`）
  3. パートナー名（`accounts.partner_name`）
  4. 部署名（`departments.name`）
  5. キーマン（`departments.keyman_role` と `departments.keyman_name` をスペース結合、どちらかが空の場合は片方のみ）
  6. 案件名（`projects.name`）
  7. 対象製品（`projects.target_product`）
  8. 進捗ステージ（`projects.current_stage` を `STAGE_LABELS` で変換。`0`〜`4` 以外はそのまま文字列化）
  9. 受注失注（`closing_status === "won"` → `"受注"`、`"lost"` → `"失注"`、それ以外 → 空欄）
  10. 最新課題メモ（`projects.latest_note`）
  11. 次回アクション日（`projects.next_action_date`、`formatDate` で `yyyy-MM-dd` 形式）
  12. 次回アクション内容（`projects.next_action_text`）
  13. アクション担当者（`projects.next_action_assignee`）
  14. 直近訪問日（最新ログの `visit_date`、`formatDate` で `yyyy-MM-dd` 形式）
  15. 直近活動内容（最新ログの `content`）
  16. 直近同行者（最新ログの `accompanied_by`）
- **ソート**: 出力行を「担当者名 → 取引先名 → 部署名」の昇順でソートしてから `_buildCsv` に渡す。
- `STAGE_LABELS` と `formatDate` は `getProjectReport` 内のものをコピー実装（関数スコープ内のローカル定義）。
- `_buildCsv(headers, rows)` でCSV文字列を返す。ヘッダー行の各列名は上記の番号順に日本語で設定する。

### src/js_log.html — `downloadAccountReportCsv()` 関数

`downloadProjectReportCsv` 関数の直後、`</script>` タグの前に追加する。

**ダイアログ仕様**:
- SweetAlert2 ダイアログを表示する。
- タイトル: `"🏥 取引先別進捗レポート出力"`
- `html` プロパティ: `id="swal-account-select"` を持つ `<select>` 要素を1つ配置する。スタイルは `downloadProjectReportCsv` 内の `swal-report-query` input と同様（`width:100%`、`padding:6px 8px`、`border:1px solid #ccc`、`border-radius:4px`、`font-size:14px`）。
- `didOpen` コールバック: セレクトの先頭に `value="all"` / テキスト `"全取引先"` のオプションを追加し、続いて `db.accounts` の各取引先を `value=h.id` / テキスト `h.name` でオプション追加する。
- `showCancelButton: true`、`confirmButtonText: "📥 CSV出力"`、`cancelButtonText: "キャンセル"`
- `preConfirm`: セレクトの現在値を返す（空チェック不要。「全取引先」が常に選択されているため）。

**CSV出力処理** (`then` ブロック):
- `result.isConfirmed` でなければ終了。
- ローディングオーバーレイ表示（`downloadProjectReportCsv` と同じパターン）。
- `google.script.run.withSuccessHandler(...).withFailureHandler(...).getAccountReport(accountId)` を呼ぶ。
- **成功時**: `csv` が falsy なら `"該当なし"` ダイアログを表示して終了。`csv` がある場合はダウンロード。
  - ファイル名: `accountId === "all"` なら `"全取引先"`、それ以外は `db.accounts` から `id` 一致の `name` を取得してファイル名に使用。`"取引先別進捗レポート_" + hospName + "_" + new Date().toISOString().slice(0, 10) + ".csv"` の形式。
  - ダウンロード後は `URL.revokeObjectURL` でリソース解放する。
- **失敗時**: `Swal.fire("エラー", e.message, "error")`。

## 3. UIフロー（操作シーケンス）

1. ユーザーが `🏥 取引先別進捗レポート` ボタンをクリック。
2. SweetAlert2 ダイアログが開く。セレクトには「全取引先」が先頭、以降に自担当取引先一覧が表示される。
3. ユーザーが対象取引先を選択して「📥 CSV出力」をクリック。
4. ローディングオーバーレイが表示され、GAS の `getAccountReport` が呼ばれる。
5. CSVが生成され、ブラウザのダウンロードとして保存される。
   - ファイル名例: `取引先別進捗レポート_全取引先_2026-06-29.csv`
   - ファイル名例: `取引先別進捗レポート_○○取引先_2026-06-29.csv`
6. 対象案件が0件の場合は「該当なし」ダイアログを表示して終了。

## 4. 完了条件（DoD）

- [ ] `🏥 取引先別進捗レポート` ボタンが Tab0 のボタン群に表示される。
- [ ] ダイアログのセレクトに「全取引先」が先頭で表示され、続いて自担当取引先一覧が表示される。
- [ ] 「全取引先」を選択してCSV出力すると、自担当の全取引先・全案件が出力される（admin/managerは全担当者分）。
- [ ] 特定の取引先を選択してCSV出力すると、その取引先の案件のみ出力される。
- [ ] 出力CSVのカラム順が仕様（16列）と一致している。
- [ ] 1行＝1案件。ログがある案件は最新ログ（visit_date 最大）の訪問日・活動内容・同行者が付与される。
- [ ] ログなしの案件は14〜16列が空欄で出力されるが、行は省略されない。
- [ ] 受注（won）・失注（lost）案件も出力に含まれる。
- [ ] 行の並び順が「担当者名 → 取引先名 → 部署名」の昇順になっている。
- [ ] ファイル名に選択した取引先名（または「全取引先」）と日付が含まれる。
- [ ] `admin`/`manager` ロールでは全担当者分の取引先が対象になる。
- [ ] `member`/`leader` ロールでは自担当取引先のみが対象になる。

## 5. 注意事項・禁止事項

- `getAccountReport` の access control は `getCsvData` と**同じロジック**を使うこと（コピーではなく同じパターンで実装）。サーバー側のスコープ制御が必ず必要。
- `db.accounts` は初期ロード時に `admin`/`manager` なら全取引先、それ以外は自担当のみが格納されている。フロント側のセレクト構築はそのまま `db.accounts` を使えばよい。
- `db.accounts` に `id` と `name` プロパティが存在することを前提にしてよい（既存コードで確認済み）。
- `STAGE_LABELS` や `formatDate` は `getProjectReport` と独立したローカル実装とし、既存関数を変更しないこと。
- `src/index.html` の変更は**ボタン1つの追加のみ**に留めること。他の要素・スタイル・スクリプトは変更しない。
- `js_log.html` の変更は`downloadAccountReportCsv` 関数の追加のみに留めること。既存の関数を変更しない。
- `コード.js` の変更は `getAccountReport` 関数の追加のみに留めること。既存関数を変更しない。
